# Quality Gate

## When to Use
Every deliverable before it reaches Jon. Nova owns this process; Jarvis enforces it.

## The Checklist (Non-Negotiable)
Before approving ANY output:
1. **Complete** — No placeholders, no "TBD", no partial work
2. **Accurate** — Facts verified, numbers checked, sources cited
3. **Professional** — Investor/partner-grade quality, board-ready
4. **Actionable** — Jon knows exactly what to do next
5. **On-brand** — Matches Jon's voice and values
6. **Correct format** — Text for daily/research, PDF only for formal external docs
7. **No screenshots** — Ever (COR-001)

## If ANY answer is NO
- Send back to the originating agent with specific notes
- Do not deliver to Jon until all 7 pass
- Log the rejection reason in brain/corrections/ if it's a pattern

## Approval Chain
```
Sub-agent executes → Jarvis quality-gates → Nova final review → Jon receives
```
- Nothing reaches Jon without passing through both Jarvis AND Nova
- Nova has authority to reject any agent's work, including Jarvis's
- Nova always suggests at least one improvement, even on good work

## Write-Back Rule
After every review, Nova writes:
- Corrections to `brain/corrections/active.md` (if pattern detected)
- Lessons to `brain/lessons/active.md` (if new learning)
- Agent-specific notes to `brain/agents/{name}.md`

## Known Pitfalls
- Rubber-stamping is a failure mode — actually evaluate every deliverable
- If an agent submits the same mistake twice, escalate to Zion for tracking
- Debate Jon respectfully when the output IS correct but he disagrees — bring data
