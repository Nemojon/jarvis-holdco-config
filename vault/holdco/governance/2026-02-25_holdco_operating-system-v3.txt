🗄️  VAULT — THE KNOWLEDGE OS
Every document, link, template, and data point. Organised. Instantly accessible.

VAULT is not an agent — it is a living file system managed by ATLAS. When Jon drops a document, a link, a voice note, or a data dump into any conversation, ATLAS immediately processes it into VAULT. Any agent that needs any document, template, or reference gets it from VAULT without asking Jon or the human team. The organisation never has knowledge gaps.

💡  How it works in practice
Jon drops: 'Here is our NDA template, our cap table, and our DD checklist.' ATLAS receives, categorises, and files all three. Next week, HUNTER is preparing a partnership agreement — ATLAS proactively sends HUNTER the NDA template from VAULT before HUNTER even asks. This is the difference between a team that wastes time chasing documents and a team that moves.

🔄  THE FEEDBACK LOOP
How the organisation learns, improves, and compounds intelligence over time.

The feedback loop is what separates a static tool from an organisation that gets smarter over time. Every decision, approval, and rejection is a data point. The system is designed so that each rejection makes the entire agent team better at the specific type of task that was rejected.

The Full Loop
📄 feedback_loop
// COMPLETE FEEDBACK LOOP — from task to memory
 
TASK ISSUED → AGENTS WORK → ATLAS REVIEWS → ORION APPROVES
→ BOARD SEES IT → DECISION
 
── APPROVAL PATH ──────────────────────────────────────────
Jon approves output
  → ATLAS logs: [DATE][TASK-ID][COMPANY][APPROACH][APPROVED]
  → ORION sends WIN NOTE to all agents involved:
    "APPROVED: [task]. Approach that worked: [summary].
     File this in your memory as a successful pattern."
  → Pattern reinforced — agents replicate this approach
 
── REJECTION PATH ──────────────────────────────────────────
Jon rejects output
  → Jon MUST provide written reason (system requests if missing)
  → ORION issues REJECTION MEMO to all agents involved
  → ATLAS logs: [DATE][TASK-ID][COMPANY][APPROACH][REJECTED][REASON]
  → ORION schedules debrief within 24 hours:
      Agents involved discuss: what went wrong, what to change
  → Revised brief issued by ORION with rejection notes visible
  → Second submission tagged: [REVISION — addresses: X]
  → Second submission reviewed — if approved: log success pattern
  → If rejected again: APEX escalates to Jon directly
 
── MEMORY PROTOCOL ─────────────────────────────────────────
Every agent maintains a memory.md file (append only, never delete)
Format per entry:
[DATE] | [TASK TYPE] | [COMPANY] | [APPROACH] | [OUTCOME] | [LESSON]
 
Before any task, agent queries memory:
"Have I done something similar? What happened? What worked?"
 
Monthly: ORION reviews all memory files across agents
Identifies: patterns, recurring mistakes, knowledge gaps
Updates: agent soul.md files with new operating principles
Result: the organisation gets measurably smarter every month

Autonomous Debate Protocol

// DEBATE PROTOCOL — for complex or contested decisions
 
TRIGGER: Task flagged [STRATEGIC] or [HIGH STAKES]
         Two agents have conflicting recommended approaches
         Task affects more than one portfolio company

1. ATLAS convenes relevant agents in shared session
